# Журнал изменений

[English](CHANGELOG.md)

Каждая публикация BooHarness в этот репозиторий добавляет сюда запись. Новые записи сверху.

## 2026-10-27, пятая публикация

Три исправления по отчёту пользователя.

- Исполнители orch больше не падают при старте с `CLAUDE.md: missing product bullet **Modules (task 2409):**`. В шаблоне CLAUDE.md комплекта есть пункт Modules, который читает контракт исполнителя, а сборка комплекта падает, если orch не может прочитать контракт исполнителя или правила code-intel из поставляемого CLAUDE.md.
- Исполнители Claude стартуют без модов Claude Code. Раньше мод из `CLAUDE_CODE_PLUGIN_DIRS` (мод handover) добавлял свой MCP-сервер в исполнителя, и проверка инициализации MCP останавливала его с `Claude worker MCP init mismatch`.
- Мод collision-guard поставляется со своим `tsconfig.json`, поэтому среда модов больше не оставляет неотслеживаемый файл в checkout.

## 2026-10-27, четвёртая публикация

- Доска orch: на карточке исполнителя есть значок `lessons` — сколько уроков ему доставлено: `N full` (полный текст в брифе) и `N on demand` (только заголовок; исполнитель читает урок, когда он нужен).
- Протокол ревью: ревьюер проверяет изменение и на соответствие требованию (`requirement gap:`), и на лишний объём (`overbuilt:`). Вердикт REQUEST_CHANGES называет, кто исправляет каждый блокер: исполнитель, лид (пробел в брифе или плане) или оператор (изменение требования).
- Подготовка к гейту роста сложности при коммите: у install-harness новый шаг `py-tools` (`--only py-tools`), а `main.ts check-on <host>` запускает этот установщик на хосте после npm. В разрешённом списке инструментов появились crapper и dryer. Самого гейта и его Python-инструментов (`ops/py-tools`) в комплекте нет, поэтому установка из комплекта показывает этот шаг как `skipped`.

## 2026-10-27, третья публикация

- README: в таблице ролей теперь все двенадцать ролей исполнителей; не хватало Tester, Designer, Copywriter, Legal и Security. Добавлена оговорка: в комплекте нет навыков правовой проверки и редактуры в стиле продукта.
- Этот журнал. Публикация теперь отказывает, если комплект изменился, а записи здесь нет.

## 2026-10-27, вторая публикация

- Документация, которая ссылается на файл не из комплекта, помечает его как `not in this kit`; ссылки на исходники оверлея установщика ведут на путь, где файл лежит в комплекте.
- Навыки и документы больше не отсылают к документу с правилами интерфейса, которого нет в комплекте.
- INSTALL.md: таблица семейств называет kimi k3.1-pro и совпадает с поставляемой матрицей ролей.
- orch: скауты glm работают на glm-5.3-flash с высоким усилием (effort high).
- orch: исполнители на удалённом хосте создают файлы с umask 022, а не с umask ssh-сессии хоста.
- Проверка топологии хуков: проба снимает метки именно тех сессий, которые использует.
