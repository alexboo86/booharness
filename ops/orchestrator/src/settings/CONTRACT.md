# Module: ops-orchestrator-settings

## Purpose

BooHarness setting declarations, effective reads, validation and serialized CAS publication.
Category declarations include runtime admission, routing and placement controls; the settings UI is outside this module.

## Public API

| Export | Contract |
|---|---|
| `defineSetting(entry)` | Register a unique declaration with nonempty one-line label/help, group (seats/models/tools/automation/safety/privacy), basic/advanced tier, control, user/operator-only class, category, scope, type, default, bounds/options, optional itemPattern (a shape rule every list item must match; for a list, bounds are item counts, so `min: 1` refuses the empty list), apply timing and consumers (reads). Optional `readOnly?: true` marks observational rows; other supplied values and read-only secret controls refuse registration. Incomplete metadata refuses registration; adapters undergo the same validation. |
| `initializeSettings(options)` | Explicitly configure the process service; returns a store for a daemon runtime. No filesystem reads or writes happen on import. |
| `readInstallSetting(stateDir, key)` | Synchronous read of one install-scope value for a read site that cannot await; reads the file on each call, refuses an unknown key or another scope, throws on a corrupt file or an invalid stored value. |
| `readAdvisoryInstallSettings(stateDir, defaults, flags)` | Delivery-only reads of install settings; on any settings read error, return the supplied defaults and append one settings-error flag. Review and refusal paths use the strict reader instead. |
| `getSetting(key)` | Read one `{schema, value, source, revision}` from the initialized service; unknown keys refuse. |
| `listSettings()` | Read `{settings, revision}` from the initialized service. |
| `putSettings(changes, revision)` | Validate and atomically publish the whole batch plus its history, or refuse with SettingsError status 400/403/409. Read-only keys refuse with 400 naming the key and reason, before publication or history. Store methods accept an optional trusted actor (operator by default, or lead <handle>); surfaces derive actors, never accept an operator claim from input. |
| `resetSettings({key}\|{group}, revision)` | Reset exactly one key or group through the same authorization, CAS queue and publication path. Selecting a read-only key (including by group or at its default) refuses the batch with 400 naming the key and reason. Changed install overrides are removed; changed required project/link values are restored explicitly. Already-default writable values are a no-op: no file write, audit entry or revision bump; authorization and CAS still apply. |
| `listSettingHistory()` | Read persisted `{history, revision}`; store method is `listHistory()`. History entries contain key, group, who, when, old, new, revision and set/reset operation. |
| `createSettingsStore(options)` | Create an independently configured store with the same three read/write methods. HTTP and MCP share one store per runtime. |
| `SettingsLinkAdapter` | `read()` supplies declarations, current values, source (one file string or a per-key file map) and source fingerprint; `prepare(changes)` validates and returns original/next file texts without writing. |
| `composeSettingsLinks(...adapters)` | Join link adapters into the store's single links slot. Overlapping declared keys refuse; fingerprints include every owner, sources stay per-key, and preparation dispatches only each owner's keys. |
| `createRatchetSettingsAdapter(repoRoot)` | Link gates.maxFileLines to the existing baseline's threshold, preserving all other baseline fields and using the shared publisher. The surface composes it with the S2a role adapter. |
| `publishSettingsFiles(plans, stateDir)` | Low-level publisher; caller holds the state-directory lock and has recovered any prior intent. Persist a fsynced, atomically renamed undo intent before staging sibling files. Removing the intent commits the complete batch. Errors undo the batch; failed undo retains the intent and blocks store reads until recovery succeeds. |
| Jev defaults | Pure default constants (`BRIEF_WORDS`, `WIDE_BRIEF_P`, `WARN_BRIEF_P`, `SKIP_LOGIC_RISK`, `RAISE_LOGIC_RISK`, `REPORT_WARN_WORDS`, `FINISHED_P`, `SUPPORTED_P`, `SAME_DEFECT_P`), re-exported under the existing owner names to avoid a settings/runtime import cycle. |
| Types / errors | `SettingDefinition`, `SettingValue`, `SettingGroup`, `SettingsActor`, `SettingsHistoryEntry`, `SettingsStore`, `SettingsOptions`, `SettingsPublication`, `SettingsError`. |

## Inputs

- Install `<stateDir>/settings.json`: `{revision, values, history, linkDefaults, gatesOff}`. Older install documents with only revision/values migrate on write without losing either field. An absent install file starts at counter zero with declaration defaults. Invalid audit data errors by path.
- Tracked `.agents/harness-settings.json`: `{version: 1, values: object}`, read by the plain-JS `readHarnessSettings` entry. Missing/invalid files or missing project values are errors naming the file; project defaults are not compiled fallbacks.
- Role links: `roles.<existing-role>.skills` and `.mcp`, backed by the existing role files, never a copy in settings.json.
- File-size link: `gates.maxFileLines`, backed solely by `docs/architecture/large-file-ratchet-baseline.json` (not in this kit)'s `threshold` (shipped 1500). No project/install value copy is written.
- Internal recovery files in the install state directory: settings.json.intent (version 1; original/next texts, sibling temporary paths and modes) and .harness-install.lock (owner pid and process start time). Neither is request-controlled. The intent contains original/next data and is private (0600); the lock contains only owner metadata.

## Outputs

- Effective values and schemas with provenance. Revision is an opaque `counter:sha256` CAS token: the persisted install counter plus a fingerprint of install/project/link sources (including linked catalogues).
- Whole-file atomic replacement of install/project values and prepared link files. Rejected batches leave all value files unchanged.

## Invariants

- Pult preferences live in the pult category, under pult.ui-theme, pult.ui-settings
  and pult.locale. Defaults match the vendored theme, developer-tools and locale
  owners; completion notifications and sound default on and density defaults
  comfortable. They are install-scope user-class live preferences, published
  through the same CAS, validation and history path as all other settings.

- Optional `SettingDefinition.readOnly` marks externally owned observations: set and key reset refuse even for the operator; group reset excludes them. Persisted install overrides refuse rather than become a second configuration writer. `memory.endpoint` observes the canonical memory client resolver (environment, service.url, localhost). `memory.embedding.model` observes MEMORYCTL_EMBED_MODEL, then the installer's local-service.json embedModel, then the store repository's harness.config.json memory.embed.model (the daemon checkout for synchronous reads); unresolved or unreadable owners yield null with an unknown source, never a guessed model. `memory.reranker.model` describes the worker's MODEL pin, not availability. Neither observation probes remote health; help/reads identify the owners.
- Seat memory delivery settings default to lessons/knowledge on, a null (byte-budget-only) full-lesson count and a 5000 ms Jev timeout. Consumers resolve each once per brief; `SEAT_JEV_TIMEOUT_MS` overrides the timeout. No memory database or daemon writer is created by these declarations.
- `gates.maxFileLines` is an operator-only linked positive safe integer. The owner baseline supplies its initial default; the existing link-default capture preserves reset across restarts. The large-file gate reads that same threshold. Commit admission requires a fresh matching operator audit in the main checkout for raises, not lowers.
- `gates.complexityEnabled` is a required project boolean, operator-only, default true (the previously unconditional complexity gate). The tracked project file carries its value; the declaration default is reset metadata, never a read fallback. Its consumer is `scripts/check-complexity-growth.mjs` (not in this kit).
- Every declaration has explicit display metadata and class; missing label/help fails registration. Apply is live/restart/next-seat. Critical-action, autonomy, gate, permission, push, secrets-veil and instrument-install controls must be operator-only; existing role capability links are operator-only. Secret controls and gate-category declarations cannot register as user-class.
- Read-only metadata remains in public schemas so clients can disable observational rows. No actor can write or reset one; a rejected batch changes no value file, revision or history. Routine rows describe shipped definitions, not scheduler state; `apply: restart` describes metadata reload only. A category loader fault keeps store construction failing on retry; completed categories are not registered twice.
- Jev delivery thresholds jev.lessonDeliveryPercent and jev.domainPagePercent are user-class tuning; jev.historyGatePercent is operator-only. The history judgement runs manually, never in check:commit.
- MCP writes require a live chat binding and derive `lead <handle>` from it. A lead cannot set or reset an operator-only key, including via group reset; authorization is batch-wide. Operator HTTP writers use the exact daemon Origin and X-Orch-Chat guard shared with lead routes.
- Each actual set or reset value change has one attributed history entry, published in the same install-file replacement as the revision. Already-default resets, refused writes and rolled-back writes add no history. Secret values/defaults/options are redacted in API responses and old/new history; validation errors never echo secret choices.
- Link defaults are captured before the first audited mutation and persisted, so reset survives process restart. Direct external file edits invalidate CAS but are not falsely attributed as API writes.
- `gatesOff` is an observational summary of registered gate-category settings with effective false values. The commit preflight prints it and the last history entry, even before a cached pass; it never disables or skips a commit gate.
- Only declared keys and valid values can be written; no partial batch is validated or published. Integer values are safe integers within bounds; number values are finite and bounded; enums/lists are option-constrained, lists have no duplicates, an `itemPattern` constrains every list item and list bounds are item counts, percent-map entries are finite percentages totalling 100, auto-or-int and choice-auto-or-int accept `auto` or a bounded integer; string supports text/secret controls and an optional unicode `pattern` (regex source) that registration compiles and every non-null value must match. `command-list` values are at most 64 exact `{name, command}` pairs: each part is a bare identifier of at most 128 characters, with case-insensitively unique names and commands, no shell syntax, arguments or paths.
- The `jev.*` install controls are user-class and live. Their defaults preserve scope (warn 0.85/refuse 0.95), review (skip 0.2/raise 0.7/Auto per theme), brief (300 words), report advisory budget (null/off; numeric overrides warn), and grading (finished 0.5/support 0.6/overlap 0.6). Writes (including resets) require effective `jev.review.skip <= jev.review.raise` with skip < 1, and `jev.scope.warn <= jev.scope.refuse`, including stored keys outside the batch; refusals name both keys. Review count is Auto or 0–10; brief words are 1–10,000. Security review has a non-configurable minimum of one even with an explicit zero count. Report word warnings never refuse parsing or trigger schema repair.
- `seats.maxOpen` is an install integer with explicit nullable/no-limit semantics: default null means today's absence of a global cap (`seats-create.ts:218`, `createSeat`; `http.ts` seats_list schema). Runtime admission consumes it immediately before insertion.
- C2 install categories declare per-family coder caps (codex/glm 10, others 5), local placement reserves (6 cores/12 GB), supported families (all compiled families), manual routing (off, with dormant equal shares), and ahead-of-pace alerts (off). Their defaults preserve today's behavior; the runtime owns consumption and policy.
- `git.syncCommits` and `git.pushGate` are required project booleans, operator-only, shipped true. The push switch is category `gates`, so operator writes include it in `gatesOff`. Hooks read these through the plain-JS harness entry; push policy comes from the trusted main-checkout hook, while sync policy comes from the committing checkout.
- `domainLeads.enabled` (default true) and `domainLeads.domains` (default null, every domain; decision 22510) are operator-only install settings; defaults keep today's unconditional gate. `enabled=false` makes landings and seat_create behave as a repository with no domain leads — the gate returns ungated, `domainLeadsRegistered` is false — while registry assignments are kept, never deleted. A non-null `domains` list restricts gating by each path's domain and new assignments to the listed domains; unlisted paths need no owner consent, but all assignments still establish creator lead status. An empty list gates nothing, like off. The landing/create gates read settings only after a readable, nonempty registry; unavailable or empty registries remain ungated (decision #22281). With assignments present, corrupt or invalid settings fail the gate closed instead of defaulting. Consumers: `land-domain.ts` (`readInstallSetting`), `scripts/memory/domain-leads.mjs` assign (`readInstallSettings`). No schema field expresses "not applicable on a domains-less install".
- `instruments.codegraph`, `instruments.ast-grep` and `instruments.memory` default true and apply to the next seat, before local/remote admission. The global set is a ceiling: seat overrides may only remove instruments. RTK is not configurable here. `instruments.own` defaults empty, is operator-only, and advertises validated CLI pairs in each turn's context without executing them. `instruments.install` defaults true, is operator-only, and gates only the installer's code-intel step (an explicit skip still wins).
- The `lead` category (task 3459 C9) declares six install keys, each acting at its owning read site with today's default bytes. `lead.replyLanguage` is a nullable string (default null) pattern-checked by the checkout config's single language rule (`harness-config.mjs` `replyLanguageRefusal`): the installer's read site (`install-harness.mjs` `installInstructions`) prefers the stored value over the checkout config, null leaves the config the owner, and a stored value the rule refuses stops the install. `lead.permissionMode` (enum `default|plan|bypassPermissions`, operator-only, apply restart) is read once per daemon start into `LeadDriver` (`http.ts`): a claude lead started afterwards carries `--permission-mode <mode>` (`claude-lead.ts`); a provider whose `permissionModes` cannot honour a set mode, or an unreadable settings document, refuses the lead start rather than ignoring the key. `lead.restartWhenIdle` (operator-only, default on, read per `/restart` request) refuses the when-idle restart before any post or drain when false. `lead.handover` (operator-only, default on, task 3459 L1) is read by the supervised lead's self-handover extension at every turn end and immediately before any pending restart, including permission-card settlement and async verification (`lead-handover.ts` in the surface module): false stops the ask and any pending restart, and a document the reader refuses stops them too, with one status frame naming the read failure — a restart nobody verified must not run on a guessed toggle. `lead.adhdRules` is operator-only (the project contract mandates the rules for lead replies, so a lead cannot switch them off); the checkout config's `lead.plainStyle: false` overrides a stored `lead.adhdRules: true` — plainStyle keeps the rules off whatever the key says. It is consumed by the session-start hook through the plain-JS `readInstallSettings` entry, never orch TypeScript; a corrupt document or invalid stored value is the one permitted fail-open in this module — one fixed-category stderr line naming the path, never the reader's message, and today's behaviour for the key — because a hook must not block the lead (covered by the lead-rules block of `scripts/test-session-start.mjs` (not in this kit)). `lead.secretsVeil` (operator-only, default on, task 3459 L3) masks a supervised lead's tool results before its model reads them (the vendored secrets-veil mod, reused through `secrets-veil-mask.mjs`); `lead-driver.ts` reads it per child spawn and passes it to `buildSpawn`: false gives raw results and one status line at spawn says so, and an unreadable document keeps the mask on and names the failure in one status frame. A mask failure withholds the result either way.
- The machines category declares exactly three install settings. machines.defaultPlacement is user-class, default any, and supplies omitted needs at seat creation; explicit needs/hosts and host-bound scouts keep their existing placement path. A configured non-any default uses the explicit-need validation and refusal path, never the omitted-any probe fallback. machines.retentionMultiplier is operator-only because it controls machine-wide automatic closure/removal: default 1 preserves the two-day terminal-turn unlanded idle close and the one-day post-close checkout grace; both intervals scale together. Landed, failed and never-prompted close floors, backup/content-identity/ownership guards, and the daily over-cap retry remain unchanged. machines.autoCodegraphInit is operator-only because it controls machine-wide tool initialization; default true preserves local/remote seeding and init, false skips only codegraph init setup lines (and their seed), never dependency installation, MCP setup or instrument admission. The local provisioner passes its resolved value to provision-worktree.sh, and that hook's standalone SessionStart path reads the same install boolean through the plain-JS entry; malformed/unreadable settings skip only the optional index, without blocking the hook. Consumers read install settings at each create, provision or retention decision, without adding project fixture requirements.
- Install defaults apply only when an install override is absent. Required project and linked values never fall back to declaration defaults.
- `logic.independence.authorReviewer`, `.debaterDebater`, `.planAuthorCritic` and `logic.recheckMode` are install-scope operator-only enums. Defaults retain family-plus-model author/critic separation, model debater separation and automatic correction routing; lower independence levels are explicit operator choices.
- The queue serializes reads/writes within a store. Publication has no asynchronous gap. All store reads and writes take the same state-directory lock. Live owners refuse with 409 regardless of age; dead owners are reclaimed using the installer's serialized, generation-safe takeover and inode-safe release. External source edits invalidate the revision and original-byte checks.
- All validation and link preparation finish before staging. A durable undo intent is published before any value-file mutation. After process death at any publication or recovery step, the next store access restores the pre-batch files (including an absent install file), or sees the entire committed batch and its audit entries. No store read exposes a partial batch. Removing the intent is the commit point; recovery is idempotent and precedes every snapshot under the lock. Sibling temps recorded in the intent and this store's orphan intent temps are removed. Malformed intents or conflicting external edits fail closed with a recovery error, preserving evidence instead of overwriting unrelated bytes.
- This guarantee covers process termination on macOS, Linux and Windows. File data and the intent are fsynced; directory entries are fsynced where Node supports opening directories (POSIX). It is not a promise of power-loss durability on Windows, nor atomic visibility to raw filesystem readers bypassing the store.
- Only the surface mounts routes and supplies links: this module imports no HTTP, MCP or role-settings implementation. Requests cannot choose paths or adapters.

## Tests

- `scripts/test-orch-settings.mjs` (not in this kit): persisted round trips, stale/concurrent CAS, metadata and value validation, all-or-none operator-only refusals, key/group resets (including already-default no-ops), attributed/redacted history, linked S2a updates and defaults, project-file errors, and socket-port exact-origin/header guards on every settings HTTP writer. Child-process SIGKILL at each publication filesystem step (install file absent/present) and during recovery proves whole-batch/audit agreement, restart idempotence and temp cleanup; dead/live owner cases prove lock recovery and 409 refusal. Child termination uses Node APIs on every platform, with no POSIX-only shell/signal handler.
