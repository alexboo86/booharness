## Skill routing and vendored skills

- `.agents/domains/_skill-map.json` defines allowed skills by role, domain, trigger; `ops/bootstrap/skill-router.mjs` picks map candidates before Jev can remove any. A role default (`roleDefaults[role]`) is never removed by a Jev answer (`route()` keeps it below `NEED_P` and for cache entries lacking it; defaults stay in the Jev question, so question set and cache key are unchanged). Domain/trigger skills are removed below `NEED_P`; `skills.off` is never returned. Jev may also ADD a skill the regex missed, only for triggers marked `"jevAdds": true` (fix, completion, diagnosing-bugs, security): a second `adds-` request adds one at p ≥ 0.75 or nothing on failure.
- Map key `skills`: one entry per `.agents/skills/` directory — `class` + `requires` (data in the map, never SKILL.md front matter: vendored text is never edited). `class` first match wins: `core` (role default), `product` (in `ops/harness-kit/excluded-skills.json` (not in this kit)), `lead` (in `leadInstalledSkills`), `stack` (one technology), `method` (rest). `requires` tokens: `bin:<name>`, `mcp:<id of ops/bootstrap/mcp-servers.json>`, `service:jev`, `service:clickhouse`, `host:win`, `input:image` (the seat reads an image each run, so its model must accept image input); orch, memory, git, node, npm get no token. `scripts/check-skill-map.mjs` refuses missing/extra entries, off-vocabulary values, `core`/`product` disagreeing with its list, unknown `mcp:` ids (it does not judge `requires` completeness); the kit build drops entries of skills it leaves out.
- Kit-shipped trigger skills: `vercel-react-best-practices` (trigger `react-best-practices`, domain-web) and `vitest` (trigger `vitest-tests`), class `stack`; designer-role design skills `ui-ux-pro-max` and `emil-design-eng`, class `method`. A broad trigger regex is a candidate list; Jev decides.
- Specialist role defaults in `roleDefaults`: designer `design-direction`, security `security-and-hardening`, copywriter kit-excluded product copy + `anti-slop`, legal kit-excluded Russian-legal product skill, motion `motion-media` + `ffmpeg-skill` (task 3336; the motion skill dirs land with their slice). `anti-slop` is kit-shipped core, original to this tree (the allowlist links it because a PROVENANCE.md is a vendor marker). All other skills of these roles are trigger candidates that Jev filters; a skill becomes `core` only by becoming a default.
- Business product skills (class `product`, kit-excluded, reaching coders/reviewers only via same-named triggers in `.agents/domains/_skill-map.json`): web academy; dated Russian legal rules (152-FZ, GDPR, 38-FZ, 39-FZ — a seat flags, never decides); YooKassa payment integration; Russian-market SEO/page copy for web/. This page does not name them: the kit copy must not name a skill the kit leaves out (the builder's leak gate).
- A vendored skill keeps its upstream commit and license in its `PROVENANCE.md` and needs an operator entry in `docs/agent/harness-allowlist.md`. `PROVENANCE.md` pins every shipped runnable file by sha256 in `## Run scripts` (`node scripts/check-skill-contract.mjs --write-run-script-baseline` (`scripts/check-skill-contract.mjs` not in this kit)); `npm run check:skill-contract` fails on changed/unpinned/stale pins, a symlink leaving the skill, a lost `PROVENANCE.md`/license, or vendored markers without an allowlist link; `scripts/check-commit.mjs` (not in this kit) runs it on every commit whatever the pathspec, and runs `check-dockerfile-crates.mjs` only for `Cargo.toml`, `<project-specific>/Dockerfile`, `.dockerignore` or pathspec-magic pathspecs (mapped on the platform-shell page).
- Seat context gives the routers a 5 s Jev deadline and records why Jev did not answer (`ops/orchestrator/src/context.ts`); hooks/gates keep the client default. Only successful decisions are cached (hit only when the answering model equals `JEV_MODEL`, `ops/bootstrap/skill-router.mjs`); client failures keep map candidates. Pi seats disable Pi skill discovery, inline role-default bodies, list other routed paths (`ops/orchestrator/src/providers/pi.ts`).
