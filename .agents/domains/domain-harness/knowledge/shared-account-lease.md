## Shared-account lease

- The lease is `scripts/app-lease.mjs`, standalone (no daemon path calls it; works while orch restarts). Tests run as `npm run check:mac-perf-slots`. `scripts/perf/mac-launch-plan.mjs` holds the mac-harness window and environment (`perfWindow`, `launchConfig`, `launchEnvironment`): the default centred always-on-top window is pinned byte for byte by `scripts/test-mac-launch-plan.mjs`; `--offscreen` puts the window borderless at the main display origin, alwaysOnTop off, `booharness_WINDOW_ALL_SPACES=1`, `booharness_WINDOW_UNDECORATED=1`, `VITE_OFFSCREEN_CAPTURE_WINDOW=1`captured via peekaboo ScreenCaptureKit `see --pid <pid> --window-title booharness` or window id; nothing shows on the operator's display; window-side map: platform-shell §5d).
- Storage: `leases.sqlite` in the orch state directory, opened directly with `node:sqlite`, never through `openStore` (it would migrate the orch schema in). Tables: `leases` (+ nullable `owner`) and `lease_waits` (resource, holder, session, queued_at). `take --wait` queues a refused take; `release` posts one chat notice to the oldest live waiter per freed resource (a `win` waiter matches any win slot) by JSON-RPC chat_post to the loopback /mcp; the queue is advisory (release succeeds when orch does not answer).
- Resources: `account` (the operator's own session, always accepted) and slots `mac-window`, `mac-2`, `win-1`..`win-4` from the slot table (`scripts/perf/account-slots.mjs`: host, perf root, dev port, label; no e-mail, no password). `mac-window`/`mac-2` = roots `lead1`/`lead6` on the Mac, ports 5183/5188; `win-1`..`win-4` = roots `lead2`..`lead5` on <configured-windows-host>, ports 5184..5187. `take`/`show` print `root=`, `port=`, `label=` per slot. `win` in a take is no row of its own: inside the transaction a holder of win slots extends each and takes no other; a requester with none gets the lowest free or overdue slot (under `--takeover`), so two takes never get one slot; no free slot → exit 3 naming every holder.
- `take`/`release` need `--as` + `--session` matching a live `chat_bindings` row (read-only store open; none → exit 4). `take` is one `BEGIN IMMEDIATE` transaction: a resource held by another handle → exit 3 with holder, promised end, note, nothing written; else all named rows written, the holder's own take extends. A lease never frees itself (overdue rows stay held; `--takeover` replaces overdue only). `release` deletes every row of the handle. Unreadable lock state is never free: a lease file without the `leases` table (zero-byte included) → exit 6, bytes kept; only a take on a missing file creates it. `--db`/`--orch-db` resolving to one file → exit 2; a control character in `--note`/`--session` → exit 2; busy after three tries → exit 5. The lease does not look at processes (the lead's host check stays; recipe: the lease bullet of orch-team "The lead chat"). `scripts/test-app-lease.mjs` covers the exits, the all-or-nothing take, two takes at once.
- Seat holders: `seat:<seat id>` takes and releases with `--owner <lead handle>` + that lead's `--session` (identity = owner's live chat binding; `--owner` refused for plain handles, required for seat holders), takes only `mac-window`, `mac-2`, `win-1`..`win-4` or `win`, never `account`, never `--wait`; each seat is its own holder. An unexpired seat row is renewed, extended or released only by its stored owner, checked inside the write transaction (another owner → exit 4 naming the stored owner; a successor session of the same owner works; an expired row stays takeable). `scripts/test-app-lease.mjs` pins these.
