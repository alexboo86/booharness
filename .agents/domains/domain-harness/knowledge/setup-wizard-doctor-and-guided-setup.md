## Setup wizard, doctor and guided setup

- BooHarness installs only by an agent from `ops/harness-kit/INSTALL-PROMPT.md`; there is no interactive setup wizard and no `npm run setup`. The agent's family answer is `node ops/bootstrap/resolve-runtime-path.mjs --families`, printing `probeFamilies` of `ops/bootstrap/wizard-steps/families.mjs`.
- `node ops/bootstrap/doctor.mjs` (npm `doctor`) proves an installation and changes nothing. Checks in order: `config` (reader `readHarnessConfig`, `ops/bootstrap/harness.config.json`), `memory install` (`install-memory.mjs --check`), `skills` (`scripts/check-skills-drift.mjs --json`), `orch daemon` (`main.ts status`), `hooks` (`scripts/check-hook-topology.mjs`), `mcp`, `logins` (per family of `families.enabled`, via `checkLogin` of `scripts/lib/family-logins.mjs`), `memory service`, `hosts` (`main.ts hosts list` + one `hosts probe` per host), `role matrix` (`main.ts roles show --json`; a `roles:` refusal is a fault with `roles reset <role>`), `user entries` (`install.userEntries`; `replace` faults only when `KIT-MANIFEST.json` says `kit: harness-kit`) and `peekaboo`.
- The owning tool decides what a fault is; the doctor never repeats its rules. Row states `ok` / `fault` / `not checked` (never shown as ok). A fault names the next command or step. The run ends with the FIRST fault's next command; exit 1 with a fault, 0 without, 2 wrong argument. Children get 15 s then SIGKILL; per-check `timeoutMs` outranks it (hooks/mcp 90 s, `memory install` 400 s over its 180 s-per-device reranker check). A throw becomes a `not checked` row. Text-only tools (hooks, mcp): fault = non-zero exit AND `FAIL:` lines; ok = exit 0 AND the summary with no skip; otherwise `not checked`.
- `memory service` asks the health route at the address the memory client uses (`serviceUrl()`, `scripts/memory/service-client.mjs`: `MEMORYCTL_URL`, installed `service.url`, loopback default); the doctor holds no address of its own. No answer on a free loopback port → fault with the platform start command; a port held by another process → fault with a freeing step; a refused non-loopback address → fault naming address and route, no local start; an alive orch daemon that does not answer names the port holder from `lsof` (foreign pid = fault; the daemon's own pid or no nameable holder = `not checked`; win32 has no `lsof`).
- `peekaboo` = verdict of `peekabooVerdict` (`ops/orchestrator/src/peekaboo.ts`): ok or fault with the fix on darwin (a not-ready verdict is `ok` "optional in this kit" where `KIT-MANIFEST.json` says `kit: harness-kit`), `not checked` elsewhere; a failed import or throw is that row's fault. `scripts/test-doctor.mjs` pins rows, next commands and timeouts; a change of the JSON of `hosts probe` or `roles show --json` still needs a live `npm run doctor`.
- `doctor --fix` runs repairs marked safe (`--dry-run` prints only). A repair is `{print, argv (argument list, never a shell string), safe}`. Safe: `install-harness.mjs --only skills`, `install-memory.mjs`, `ops/orchestrator/install.mjs`, service start of an installed daemon (`launchctl kickstart`, `Start-ScheduledTask`). `--only mcp` is safe only under `install.userEntries: keep` (else it removes the user's own MCP servers); the hooks step is never safe — `stripPromptHooks` of `install-harness.mjs` still removes the code-index tool's `codegraph prompt-hook` (`scripts/test-install-harness-safety.mjs` pins that under `keep`). Never safe: a login, a secret, `roles reset`, a config change, an ssh repair, a taken port. The run prints `fix: <command>` per safe repair in check order, runs it (120 s limit), prints `fix failed:`/`fix refused: <command> — <why>`, and re-proves the installation when a repair ran.
- `--fix --json` (also with `--dry-run`) prints ONE JSON document `{ "fixes": [...], "rows": [...] }`: each fix `{command, state, detail}` with state `planned`/`ran`/`failed`/`refused`; `rows` = last proof. Repair child output never reaches stdout; `--json` without `--fix` prints the bare rows.
