## Edit-tool arms and stock rollout

The `codex-edit` arm, outside `MATRIX_ARMS`, loads only `extensions/codex-edit/index.ts` of @maxiaochao/pi-toolkit@0.9.3. Install verifies origin/integrity/sha512 before npm, disables scripts and writes arm config for gpt-6.1-sol. Settings use plain includes, other resource types `[]`; `+path` force-includes over load-all, omitted types load defaults. `ops/ab-stand/codex-edit-resources.mjs` checks Pi resolves exactly that extension. Arming requires paid-smoke delivery proof of full-access apply_patch; edit-metrics reports per-arm first-edit success.

`codexEditWanted`/`codexEditEligible` (`ops/orchestrator/src/codex-edit.ts`) select only full-access stock Pi codex seats: not read-only, native, stand arms (including base) or win32 targets. Windows keeps built-in edit/write because the pinned toolkit's forward-slash workspace guard rejects nested Windows paths; existing installs remain. Darwin/Linux are unaffected.

`ops/ab-stand/codex-edit-install.mjs --ensure|--check [--prefix]` uses `ops/ab-stand/codex-edit.json` pins shared with the arm. All reads/writes/deletes stay within a realpath prefix; internal symlinks/junctions refuse. Failed verification clears package/record before repair. Local prefix is `<stateDir>/pi-extensions/codex-edit`; eligible starts check asynchronously and fail with repair command, without stock-edit fallback. Hosts provision `<host.repo>/.pi-extensions/codex-edit`, recorded on the seat and rechecked each start. Unrecorded remote paths are installed lazily by `provisionPinnedEdit` (`ops/orchestrator/src/remote-provision.ts`), serialized per host/extension and recorded before checking; mismatched recorded paths fail. `piExpectedTools` swaps edit for apply_patch only when loaded; apply_patch participates in mutating-tool verification.

Codex installs use `npm ci --ignore-scripts --bin-links=false` with committed `ops/ab-stand/codex-edit-lock.json`, or `codex-edit-stand-lock.json` for pi-mcp-adapter@5.3.2; other extra packages refuse. `ops/ab-stand/npm-install-tree.mjs`, shared with hashline, requires locked sha512 and pinned-registry resolved URLs, hashing every regular node_modules file and refusing links/special files. `install.json` binds `lockSha256` and tree. Check rejects missing/stale records, changed npm inputs, added/removed/changed files and wrong locked versions, skipping optional packages omitted for the platform. Reinstall removes all node_modules and the record before fetching. The tree covers node_modules, not other prefix-root entries. `scripts/orch-seats-test-helpers.mjs` (not in this kit) copies verified stock prefixes into temporary state and checks them unstubbed; missing machine installs produce an ensure-repair fixture error.

`hashlineEditWanted` (`ops/orchestrator/src/hashline-edit.ts`) selects stock full-access Pi qwen/grok/mimo, excluding stand arms, read-only and native seats. `ops/ab-stand/hashline-edit.json` pins hashline-edit 4.5.1 and typebox@1.3.34 for stock and `hashline-edit-451`. `hashline-edit-install.mjs --ensure|--check [--prefix]` shares codex npm/confinement primitives. Stock uses `ops/ab-stand/hashline-edit-lock.json` with `npm ci --ignore-scripts --legacy-peer-deps`; every dependency has npm-checked tarball sha512 and the main integrity matches shared pins. Records bind lock digest and complete node_modules sha256 tree; starts detect additions/removals/changes and links, and check upstream source hashes. Readiness requires rg and false `copyMoveEnabled`/`anchorGrepEnabled`. Repair clears tree/record; version-only records are stale.

Hashline prefixes are `<stateDir>/pi-extensions/hashline-edit` and `<host.repo>/.pi-extensions/hashline-edit`; `PI_HASHLINE_DIR` is their `hashline` subdirectory, not stand stores. Local starts check asynchronously; remote provisioning installs/records, and starts recheck without stock fallback. Verified loadouts keep hash-anchored read, replace edit with replace/insert/undo_last_change; copy/move and anchor_grep remain disabled. All registered hashline mutators participate in verification.

`node ops/ab-stand/run.mjs --pilot codex-edit --reps N` alternates base/codex-edit on edit-only `edit-1`/`edit-2`. `scoreEdit` (`ops/ab-stand/scorer.mjs`) checks mustChange/owned diff paths, not tests. Cells retain matrix guards, caps, usage and activation-proof hash; cellKey adds `cohort: pilot:codex-edit` without changing matrix digests. Turns last 10 minutes; invocations start at most two runs, skip done/capped/error and reconsider deferred. `ops/ab-stand/report.mjs` groups arm/family/task/config, not cohort; matrix/pilot tasks are disjoint.

Pilot `hashline-edit` runs base/hashline-edit-451 on kimi/mimo/qwen/grok with per-family guards/caps and 5-minute turns; `ops/ab-stand/auth.mjs` requires Kimi OAuth's one-minute margin, while qwen/mimo use Token Plan api_key. Pilot-only `--pace-override "<operator reason>"` skips quota reads; pilots never read matrix budget-start rows. `hashline-edit-glm` runs glm alone.
