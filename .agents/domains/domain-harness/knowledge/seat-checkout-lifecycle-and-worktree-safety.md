## Seat checkout lifecycle and worktree safety

- Checkouts resolve through `git worktree list --porcelain` (`repoOf`, `ops/orchestrator/src/worktrees.ts`); during another seat's `worktree add` the reader retries once after 50 ms, then builds the list itself (main from `--git-common-dir` plus each `worktrees/<n>/gitdir` whose commondir is written). `coderRepo` (`ops/orchestrator/src/prune.ts`) reads a gone lead's main checkout through it with its own 15 s git timeout. `createWorktree`/`removeWorktree` (`ops/orchestrator/src/worktrees.ts`) take one turn per common git directory on a keyed FIFO (`createKeyedQueue`, `ops/orchestrator/src/keyed-queue.ts`); main and linked checkouts share the key. `withHostClone` (`ops/orchestrator/src/remote-repo.ts`) is the same FIFO keyed by host.
- A seat worktree's codegraph daemon (pids `<root>/.codegraph/daemon.pid`, `writer.pid`; registry `~/.codegraph/daemons/<hash>.json` `{root, pid, socketPath}`) is stopped before worktree or cache removal: `stopCodegraphDaemon` (`ops/orchestrator/src/worktrees.ts`) signals only a pid whose `ps` names codegraph `--path <root>` or whose registry entry names the root (SIGTERM, SIGKILL after 2 s; win32 no-op; another root's pid skipped); `removeWorktree` calls it before `git worktree remove`, `clearCaches` before `.codegraph`; `noteCodegraphDaemonStop` stores `seat.codegraph_daemon_stopped` `{seat, root, stopped, skipped}` only when a daemon stopped. A live seat's MCP stdio front is never touched.
- The 10-min sweep (`pruneLandedSeats`, `ops/orchestrator/src/seats-close.ts`) must not block the event loop: 500-row keyset pages (`pruneCandidatesPage`, `ops/orchestrator/src/store.ts`), one `setImmediate` per candidate (`scripts/test-orch-prune-sweep.mjs` (not in this kit) pins each stretch under 50 ms). `checkoutInUse` (`ops/orchestrator/src/prune.ts`): a host seat's `cwd` is compared as written, never resolved on the Mac. CLI `prune --caches` (`ops/orchestrator/src/main.ts`) reads every closed seat, one-shot.
- A local coder's checkout survives close and `seat_land`; a remote coder's host checkout is removed only after its bytes are mirrored (`ops/orchestrator/src/seats-provision.ts`). Invariant: a host checkout is never removed while the mirror lacks its tree (close rereads `remoteSyncState`, re-syncs, refuses until the snapshot exists locally). `snapshotBack` pins `refs/orch/snapshots/<seat>` before the mirror reset; `removeMirror` deletes the ref first. Landing is one `git apply --3way`, no commit (`ops/orchestrator/src/land.ts`).
- Offline `prune --dry-run`/`prune` (`ops/orchestrator/src/prune.ts`): local coders compared per changed path vs repo HEAD; unknown untracked/ignored files refused even with `--older-than 7d`; remote mirrors need landing proof, not age; dry-run lists lost paths; foreign paths/branches and open seats refused.
- Every 10 min the daemon removes a closed local coder's worktree and branch only when the landed check vs lead HEAD says the whole change is there, the branch tip equals its tip at close, ignored files are byte-identical and HEAD/tip re-read unchanged (`autoPruned`, never operator approval); bounds 120 s per seat, 30 s per Git call, 64 MiB. It also closes a ready reviewer/bughunter idle 24 h with no running or queued turn, closes a coder idle 24 h only on a no-change or fully-landed proof, and sends closed remote coders through pruneCoder/pruneMirror; `unknown` and every error keep the seat.
- A coder closes two days after its last turn even without landing proof (never with running/queued turns, a concurrent turn on its checkout, or deferred replacements); at least a day later unlanded checkouts and final mirrors age: a missing lead checkout resolves through the checkout's common Git directory against master; `<stateDir>/worktree-backups/<seat>.patch` and the unsafe-file archive precede a `checkoutOnly` marker (`capRule: 2`) holding repository and content identity (HEAD, non-ignored tree, a SHA-256 over archived hashes and the ignored-name set, rechecked before removal); mirror backups are rechecked before removal and on restart; an existing backup is never deleted; the branch `orch/<seat>` or snapshot ref stays; `prune --older-than` never discards an unlanded mirror.
- Reviewer checkout is disposable (`ops/orchestrator/src/seats-close.ts`); with the lead checkout gone, removal runs git in the worktree's common git directory (`ops/orchestrator/src/worktrees.ts`); a resolution failure stays per-seat. `idleFloorDays` (`ops/orchestrator/src/prune.ts`): coder half a day (needs the landed/no-change proof), other roles one day; the two-day unlanded close and the one-day wait before checkout removal are separate rules.
