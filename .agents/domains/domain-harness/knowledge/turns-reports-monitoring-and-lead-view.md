## Turns, reports, monitoring and lead view

- `seats_list` (`ops/orchestrator/src/http.ts`): one seat in full by id, open seats in full, closed only when asked (compact rows, 50 per page, `closedPage`). `ops/orchestrator/src/report.ts` defines the one-block JSON report; the parser rejects structural errors (not length) and repairs malformed replies within the turn budget.
- Grading (`ops/orchestrator/src/grading.ts`): Jev scores `realReport`; evidence support and sibling comparison are code rules. Evidence is supported when it names a command/test run, a URL, or the cited file (`evidenceSupported`); sibling findings on the same file with near lines are one defect (`sameDefect`). Unsupported or ungraded major findings are flagged. A blocker/major below 0.6 gets one support round (findings returned in place, re-evidenced, downgraded or `withdrawn`; a correction that drops or rewrites one is rejected). Grade persistence precedes the completed turn (`ops/orchestrator/src/store.ts`); the digest delivers only the parsed report or error.
- Digest flags: a `done` report whose last run of a command failed (a passing rerun clears it); a `done` report without a nonempty `criteria` list (`{criterion, check, reason?}` per acceptance criterion) goes through the bounded repair (stored reports reparse leniently); a criterion whose check is null, absent, or not passed by orch's rerun (`criteriaFlags`, `ops/orchestrator/src/digest-text.ts`).
- Prompts to a busy seat queue FIFO up to `MAX_QUEUED_TURNS`, queued resume on next start. A coder prompt overlapping another open coder's declared/observed change returns an `overlap` warning: orch reads git status/diffs of every open coder, four seats (twelve git processes) at a time; a sibling whose diff is already on lead HEAD stops counting; an unknown result stays `overlapUnchecked`.
- Recheck routing (`recheckRoute`, `ops/orchestrator/src/seats-verify.ts`): on a coder correction, each reviewer whose last report was REQUEST_CHANGES with reproduced blocker/major findings is routed from the correction delta between recorded coder trees — full coverage by the findings' citations or test files gets a same-reviewer recheck limited to those findings (model `rule`); any unnamed path brings a NEW reviewer from an unused family, briefed with the original first brief on a coder-worktree snapshot (`data.main` keeps repository, siblings, cap and keys). Waiters on a done correction are held until routing is recorded (≤90 s); post-report work registers in the per-turn `afterTurn` registry with its own hold (recheck 90 s, tree 10 s); each correction persists its delta as `recheckResults[<turn>].changedPaths` (capped at 500).
- Scope gate (`ops/orchestrator/src/seats-scope.ts`): a coder's first `seat_prompt` is Jev-scored (more than one bounded behavior, or many new units that cannot finish in one turn) before queueing,; refusal only above 0.85; `wide_brief` (≤300 characters, `ops/orchestrator/src/http.ts`) bypasses; Jev unavailable/invalid/privacy-cut passes labelled. Score or bypass reason lands on `watch.scope` (a bypass also stores reason, timestamp, creating turn id in `data.wideBrief`); the same call answers task features. Refusals log `seat.brief_refused` (`ops/orchestrator/src/seats-prompt.ts`) plus a store event; a bypass is Jev-judged in the background after queueing (`recordBypassScope`, `ops/orchestrator/src/seats.ts` → `watch.scope.bypass`, status stays `bypassed`).

- `scout_request {question, files?}` (`ops/orchestrator/src/scout-request.ts`): coder/bughunter/reviewer seats get a read-only scout seat with the caller as parent (caller card shows `asked scout <n>` — `ops/orchestrator/src/dashboard.ts`, `ops/claude-mods/orch-board/hooks/svg/seats.ts`); the digest is returned and the scout closed. Depth 1, one per seat at a time, 200-word question, no lifetime cap; calls log `seat.scout_requested`/`seat.scout_refused`. A per-session token binds the caller; /seat-mcp and the Pi extension expose only this tool; claude seats keep `--disallowedTools mcp__orch`.
- Calibration: review-plan risk answers are stored as `review.jev` events (score or failure code, thresholds 0.2/0.7; `recordJevAnswer`, `ops/orchestrator/src/review-plan.ts`), advisory only; a `drift` action in a stored turn stays readable (`TurnWatchRecord`, `ops/orchestrator/src/store.ts`).
- Pi seat bash (`ops/orchestrator/src/seat-guard.ts`): every command capped at `SEAT_BASH_TIMEOUT_SECONDS` (600 s; timeout kills the process tree and explains); a call whose unwrapped programs are all build-gate heavy builds, cmake configure, ctest or a plain `cd` gets `SEAT_BASH_BUILD_TIMEOUT_SECONDS` (45 min); a shell counts only through its `-c` payload. `refuseBroadSearch` refuses find/rg/grep at a filesystem/home/drive root (also after `cd`); worktree and named install dirs pass. Full-access coder/reviewer/bughunter Pi bash is not subject to `refuseReadOnly` (`ops/orchestrator/src/pi-extension.ts`).
- Check verification (`verifyChecks`, `ops/orchestrator/src/check-verify.ts`, wired in `settle()`, `ops/orchestrator/src/seats.ts`): a coder report claiming passing checks gets up to two reruns in the seat worktree before the turn finishes and before waiters wake. Allow-listed shapes only (`node --check`, `node scripts/check-*.mjs`, `node --test <one file>`, `node scripts/test-*.mjs`, `npx vitest run <path>`, `npx tsc --noEmit -p`, `npx eslint .`, `npm run lint`, `cargo check -p`), `shell: false`, paths realpath-confined to the worktree; caps 120 s/check, 240 s/turn. Digest tags `[verified]`/`[VERIFIED FAIL]`/`[unverified]`; closing the seat aborts as unverified; suite commands stay unverified. `scripts/test-orch-check-verify.mjs` pins the shapes.
- `ops/orchestrator/src/watch.ts` steers a supported provider on repeated tools, then interrupts; at 80% of the turn limit (`deadlineDelayMs`, `ops/orchestrator/src/context.ts`) a steerable provider gets one "report now" message asking for `partial` + `notChecked`. A provider timeout stays `error`, never `done`. `ops/orchestrator/src/seats-verify.ts` picks continued vs fresh sessions by context fill and brief similarity.
