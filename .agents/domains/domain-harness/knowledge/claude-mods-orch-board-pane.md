## Claude Code mods: the orch-board pane

`ops/claude-mods/` holds `.claude-plugin/plugin.json`, `hooks/hooks.json`, hook modules and tests. Engine-generated `.claude-plugin/types/` is gitignored; fresh checkouts cannot typecheck without a copy. Mod checks: `claude plugin validate .`, `npx tsc -p . --noEmit`, `claude plugin test .`. `CLAUDE_CODE_PLUGIN_DIRS` in `~/.claude/settings.json` loads mods into lead sessions; native claude/glm worker seats clear it in both the spawn env and `--settings` env (task 3200), so no mod reaches a seat; dev-mods prompt for hot reload, and double-listing loads twice.

`orch-board/hooks/poll.tsx` polls `http://127.0.0.1:7760/api/dashboard` and `/api/chat`; `hooks/parse.ts` validates envelopes; `hooks/svg/*.ts` draw section SVGs with compact cards, meters and tool/skill/MCP/Pi badges. `hooks/svg/header.ts` draws a separate header with status, working count, alert pills, paused-family reasons, rtk, jev and Bright Data balance; no footer image. `brightdataLine` (`hooks/sections/header-format.ts`) consumes the nullable `brightdata` field required by the parser; `ops/orchestrator/src/brightdata.ts` reads it every 10 minutes.

The `session.start` hook opens a missing pane only when `$.session.surfaces()` is nonempty; otherwise `session.attach` opens it, avoiding `no-surface`. `/clear` does not raise `session.start`, so the pane stays; reload raises it and reopens a closed pane. `ZOOM` (`hooks/register.tsx`) lays out at width/(14/13) and draws at width. Daemon strings pass through `esc()` (`hooks/svg/kinora.ts`). Fold buttons and chat/release forms stay native; `hooks/chat-api.ts` fixes base, Origin, X-Orch-Chat and a 600-code-point limit. Images are noninteractive. Without a scroll container, Chat shows the last four posts and an earlier-count; the web board keeps the full log. Pane width uses body columns times 8.9 px, clamped to 200..4096; sections above 4096 px or 131072 characters split into pages.

`badgeHues` (`hooks/svg/badges.ts`) hashes row/name with FNV-1a into hue sets: skills green, tools amber, MCP teal, Pi purple; missing is red, unused muted. Family marks precede plain family names on lead, seat and finished rows, at 1.4em; limits show reset counts without logos. `hooks/sections/family-format.ts` accepts registry keys only; `image()` (`hooks/svg/kinora.ts`) emits one family `<symbol>` in `<defs>` and `<use>` per occurrence. The mod cannot import outside its folder; `hooks/generated/family-logos.ts` is an esbuild copy of `ops/orchestrator/src/family-logos.ts`, generated by `ops/claude-mods/orch-board/scripts/prepare.mjs`. `scripts/test-orch-family-logo-copy.mjs` (not in this kit) detects stale copies.

`handover/hooks/register.ts` registers `mcp__handover__run {text, clear}`. True keeps text in a module variable and runs `/clear` after the turn; `session.end` with reason `clear` submits it as the cleared session's first prompt. Refused clear drops text; false submits a new prompt in the same session. Without the tool, the relay session remains the fallback.

Vendored mods carry `NOTICE` and `VENDOR.json` (source, SHA, license, per-file SHA-256); `review_plan` excludes hash-matching files from reviewer count. Modified files are omitted from `files` and named in NOTICE. `collision-guard` keeps per-chat ledgers in `~/.claude/mods-data/collision-guard/`, warning on shared edits via read-only `git ls-files`. `delay-no-more` restores deferred tools in `tool.describe`, writing nothing. `secrets-veil` masks 21 named secret variables and denies calls if masking fails; it emits no start notice. None makes its own network calls. `ops/harness-kit/test-prefix.mjs` (not in this kit) collects all mod files; the installer registers only `CLAUDE_MOD_NAMES` in `ops/bootstrap/permissions-target.mjs`.

`secrets-veil` masks only named values in `base64`/`data` with PNG/JPEG/GIF/WEBP/PDF signatures (`isEncodedMedia`); plain-text base64 is fully masked.
