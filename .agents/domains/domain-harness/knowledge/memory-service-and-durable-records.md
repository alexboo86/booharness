## Memory service and durable records

The kit uses one local memoryd writer at `http://127.0.0.1:7717`; see `docs/agent/memory.md` and `ops/memory-local/install.mjs`. Backup and forwarding destinations require explicit operator configuration. Do not start a second writer. Donor NAS rollback recipes are not shipped.

memoryd reloads its installed `~/.local/share/booharness/docs/agent/domain-routing.generated.json` on mtime/size changes (`scripts/memory/store.mjs`). Master-only post-merge/post-commit hooks call `ops/bootstrap/install-memory.mjs --landed-map`, reading committed HEAD, replacing unequal bytes by temporary/rename and rechecking HEAD for at most three rounds. Failures do not stop merge/commit. Reset/rebase do not invoke these hooks. `check:memory-install` checks service-code and map drift; client-only hosts report the map not compared, since only the writer reads it. Hook shims are installed by `ops/bootstrap/install-harness.mjs`; `scripts/audit-rule-sensors.mjs` detects unwired hooks.

`.claude/scripts/memoryctl` follows symlinks to source its HTTP helper. Stdin bodies refuse terminal/empty input and sentinel-only `-`/`@-` before sending. `ops/bootstrap/install-memory.mjs` validates local-service options before writing and persists them in `<state>/local-service.json`; remote mode retires all units. Embed URLs refuse userinfo/query/fragment because plists are world-readable. Forward LaunchAgents use loopback reverse ssh, ExitOnForwardFailure and 15 s keepalive, with a port distinct from memoryd. Backup scheduling stages privately under `<state>/backup-staging`.

`ops/backup-memory.mjs --ship-to` checks remote reachability before snapshot, streams to a partial generation, verifies remote sha256 and renames before remote retention: newest of seven UTC days and the eight following weeks. Failed shipping removes the unshipped generation. Shipping has a 12-minute deadline below the scheduler's 15-minute kill; health judges the last shipped generation against 26 h. SessionStart warns leads, not seats. Consolidation and anchor sweeps use the service; clients never implicitly open local memory.db. Schema 7's `mem_vectors` stores one model-stamped vector per live entry (`scripts/memory/store.mjs`).

Plain search ranks live entries by cosine using local Ollama (loopback 11434); explicit FTS5 syntax stays literal. Model selection is environment `MEMORYCTL_EMBED_MODEL`, with absent-variable default qwen3-embedding:0.6b. Installer selection is flag, saved local-service config, then tracked `memory.embed.model`; saved settings mask later tracked edits. `scripts/lib/harness-config.mjs:readHarnessConfig` reads that config once at module load; unreadable config refuses before writes, while landing hooks print the refusal without blocking.

Without a kind filter, `scripts/memory/search-results.mjs` reranks the first 30 dense rows using pinned `BAAI/bge-reranker-v2-m3`; identity hits and rows after the head retain dense order. `scripts/memory/reranker.mjs:createReranker` owns one resident JSONL child, `scripts/memory/rerank-worker.py`, which validates its dependency pin. Request timeouts discard late answers without killing the child; loads have 180 s and stop respawning after three failures. Unavailability returns dense order with `X-Memory-Rerank` and health status.

For absent/local `memory.rerank`, the installer builds `<state>/rerank-venv` and `rerank-model`, smokes one pair, then writes `MEMORYCTL_RERANK_PYTHON`. The kit omits the key and is managed on macOS. Smoke selects mps on darwin, retrying cpu after Metal/mps failure, otherwise cpu; the worker requires `RERANK_DEVICE`. Off mode writes `MEMORYCTL_RERANK=off`, needs no venv check, reports off and suppresses the header; a missing Python setting without off remains unavailable. Windows managed installs require `MEMORYCTL_PYTHON_BIN`, Python >=3.10 and `Scripts\python.exe`; ARM64 accepts the pinned torch CPU-index build. Installer output distinguishes changed-plist reload from code-only kickstart.
