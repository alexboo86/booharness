## Optional config keys and the config writer

`scripts/lib/harness-config.mjs` validates optional keys; `ops/bootstrap/harness.config.json` omits absent options rather than inventing defaults.

`mcp.off` lists known, non-required server ids from `ops/bootstrap/mcp-servers.json`; codegraph/memoryctl cannot be off. `ops/bootstrap/install-harness.mjs:selectServers` excludes them before secret/file checks. `installMcp` retires those ids from runtime configs even in keep mode, including hand-added entries with the same id, preserving other ids. TOML parsing handles bare/quoted keys and avoids duplicate managed tables (`scripts/test-mcp-ssot-render.mjs`).

`skills.off` accepts unique known non-core skills from `.agents/domains/_skill-map.json`; malformed maps refuse. Installation creates no off links and removes only managed links; drift checks expect none. `ops/bootstrap/skill-router.mjs:mapCandidates` filters every source on each call, including Jev additions. SessionStart judges the effective lead set minus off skills (`scripts/test-install-skills-off.mjs`).

`skills.lead` replaces the non-core lead set while retaining core defaults; an empty list keeps only core. Unknown, duplicate, off or support-lead-only names refuse. `effectiveLeadSkills` in `scripts/lib/harness-config.mjs` is shared by installation, drift checks and SessionStart; absent keys use map defaults. Invalid config stops installation before its first step, fails drift judgment and prevents lead-skill judgment (`scripts/test-install-skills-lead.mjs`).

`lead.replyLanguage` accepts language names of 2–40 letters/spaces/hyphens with at least one letter. `ops/bootstrap/agent-instructions.md` carries `{{LEAD_REPLY_LANGUAGE}}`; `installInstructions` renders the value or Russian and refuses unresolved IDENT tokens before writes (`scripts/test-install-instructions-language.mjs`). Kit text swaps do not replace the token.

`lead.userTextFile` accepts a control-free path up to 1024 characters without opening it. `installInstructions` resolves absolute/home/repo-relative paths and reads one descriptor before instruction writes. Missing/non-regular, >16384-byte, invalid UTF-8 or bootstrap-marker-bearing files refuse without exposing content; symlinks to regular files are followed. Text is appended unchanged inside each marked block after token/platform/runtime selection; reinstall replaces it, removing the key removes it, and outside text stays. Marker detection covers substrings throughout the text to match `ops/bootstrap/marked-blocks.mjs:replaceMarked` (`scripts/test-install-instructions-usertext.mjs`).

`lead.plainStyle` is boolean. `ops/bootstrap/session-start.mjs` emits i-have-adhd for leads when absent/true, not false; seats neither read config nor print it. The hook reads its install checkout's config. Unreadable/invalid config keeps the print and adds only a fixed-category/path warning, never config content, without failing SessionStart (`scripts/test-session-start.mjs`).

`lead.briefLanguage` sets off/flag/enforce in `<stateDir>/language.json`. The orchestrator installer step uses `ops/orchestrator/src/language.ts:writeLanguageMode` after child installation, in the child's reported state directory; the CLI shares it and the daemon rereads without restart. Absent keys leave the file untouched; non-orchestrator steps never write it. Write failure fails install with the path; skipped steps report non-application and warn. Config preflight precedes the lock and all steps when a config exists (`scripts/test-install-brief-language.mjs`).

`writeHarnessConfig` in `scripts/lib/harness-config.mjs` is the config's single writer, shared by wizard and agent paths. It accepts a whole config or a transform under the home installer lock, preventing lost concurrent changes. Canonical schema ordering, empty-branch removal, two-space JSON and final newline give equal content equal bytes; list order stays. Reader validation precedes replacement, so refusal preserves the old file. Writes fsync a sibling temp then rename, skip equal bytes, follow file symlinks and refuse dangling links/directories. Dead-pid locks and temp files are reclaimed; live-pid temps remain. `ops/bootstrap/harness-config.mjs` exposes validate/get/set/unset/apply; unset accepts optional keys only and prototype keys refuse. `scripts/test-harness-config-writer.mjs` covers atomicity and spelling.
