## Family role models and budget ranking

`ops/orchestrator/src/profiles.ts` defines role/family/model/effort. Claude takes researcher/coder/reviewer/critic, not plain scout: reviewers/critics use claude-sonnet-5-5 high, coders claude-opus-5-5 high. Scouts use opencode glm-5.3-flash, grok low, qwen/mimo flash, codex gpt-6-luna high, glm glm-5.3-flash high (task 2692 trial verdict). Kimi uses high in every role; reviewers use high, other bughunters max.

`role: critic` is read-only, one-answer, reviewer-matrix pooled and never routed. Explicit model/effort/native, out-of-matrix families and the lead family refuse, except Claude critics without Claude authors/coauthors. Optional author steps its family aside. `role: scout, critic: true` remains an alias; `plan-critic` is a role default in `.agents/domains/_skill-map.json`. `accountingRole` accounts critics separately (including stored `data.critic` scouts), using critic calibration and reviewer default reserves.

`pickFamily` (`ops/orchestrator/src/profiles.ts`) uses each family's longest applicable readable quota window (week/month). Spend at or behind linear pace forms the first group: usage plus window reserve, excluding reservations. Need is unspent share after reserve/reservations divided by remaining window share floored at 0.5%. First-group need is the maximum over matching readable token windows of at least one day; MCP counts, other-model scopes and subday windows cannot raise it. Ahead-of-pace families retain longest-window need. First-group rank is need/(1+A): provisioning/working seats in the pick's accounting role plus ready, turnless seats under 10 minutes. `pickInputs` reads A synchronously from store (`ops/orchestrator/src/seats-prompt.ts`). Ties use chain usage ascending, then name. `picked` reports winner/runner-up need, window and A. Coverage: `scripts/test-orch-seat-pick-spread.mjs` (not in this kit).

Ahead-of-pace rows rank by elapsed-minus-used headroom converted to calendar-window days. `month` labels retain actual calendar length (`ops/usage-snapshot.mjs`, `windowLength` in profiles). The group boundary is zero headroom before reservations. Readable rows without reset rank after both groups, unreadable last. Reasons show headroom/need and the reset-adjusted `aheadKey` when applicable. Shorter or equal-length matching model windows throttle; other-model scopes do not. A throttle steps aside below 5% left or when calibrated own burn cannot fit after working reservations. Without calibrated burn, it uses only the floor. Banked short resets can lower that floor as below.

`ops/orchestrator/src/limits.ts` estimates burn from pooled points/tokens across up to five usage episodes in seven days, refusing less than one mean turn's volume; outside-orch spend counts. Integer meters charge changed points to tokens since the prior change; unwitnessed episode starts only anchor. `paceReading` shares `budgetReading` across ranking, estimates and reservations. Kimi paces monthly; 5h only throttles. `ops/usage-snapshot.mjs` reads `usages.limit_month_total`; absent usage is no reading. 5h derives `limit - remaining` only from numbers/nonblank numeric strings with 0 <= remaining <= limit. Local Kimi uses Pi kimi-coding OAuth, without opencode keys or inherited `KIMI_API_KEY`.

Provider capacity/unavailable/overload errors, or an error-line-start `Codex error: Unable to verify <name> access. Please try again.`, rank a family last for 20 minutes or until completion. Auth failures rank last for 60 minutes or completion. Quota wording wins over auth, auth over outage; `providerError` (`ops/orchestrator/src/limits.ts`) excludes orch interrupts, caps, timeouts and close errors quoting arguments. Explicit families bypass outage ranking, not guards. Board/reasons expose outages/auth failures. `Limits.reading` prefers newer per-family last-good over shared readings, excluding future-dated values after clock rollback.

Open queued/running seats, or seats created since the last family reading, reserve calibrated expected burn or role `DEFAULT_TURN_BURN`. Automatic coders step aside at working coder caps (codex and glm 10, others 5); if all candidates are capped, the first-ranked family still wins. Model overrides scope window matching/estimates; named families on spent matching scopes refuse. Passed resets stay readable at 0% elapsed. Behind-pace deficit does not block a family; reservations count in headroom.

Author/coauthor/sibling-reviewer families step aside. Lead families do too except coder picks and eligible Claude reviewer/critic picks. `ops/orchestrator/src/paused-families.ts` excludes paused families even when named; CLI `main.ts pause <family> --reason "<why>"|unpause|paused`. Records are `{family, reason, at}`; trimmed reason max 200 characters, legacy bare names read `unknown (legacy)`. Malformed pause files fail closed: pick refuses, board exposes `pausedError`, handoff draft errors. Board/reasons/drafts show age/reason with control characters replaced; `picked` warns if the paused family would have won.

`WINDOW_RESERVE` (`ops/orchestrator/src/profiles.ts`) reserves 5% for GLM's shared hermes-agent key on every token window, never MCP counts or other families. `reserveHit` excludes GLM from eligible/emergency picks and refuses explicit creates with `glm reserve 5% kept for hermes-agent` (`ops/orchestrator/src/seats-create.ts`). Generic minimum/throttle reasons can step it aside before the reserve-specific reason.

`rankFamilies`/`pickFamily` count unexpired available banked resets by scope: week/both add `weekResets`, 5h/both add `shortResets`. Ahead-of-pace order is `headroomDays + 7*[weekResets >= 1] - 0.5*A`: binary weekly credit and per-working-seat penalty affect rank only, not need/headroom/spend-first order. Short resets lower shorter-window throttle floors to zero, but spent windows and calibrated burn still step aside. Orch never redeems resets. Reservations charge each seat's own `pace` window and each `burns` entry's window, not equality with the pick budget; unreadable pace retains budget-label charging. `picked` shows reset counts, `(throttle lifted)` only when effective, next eligible runner-up (fallback if all stepped aside), and `resets unknown` only for explicit null. Coverage: `scripts/test-orch-usage.mjs` (not in this kit), `scripts/test-orch-seat-pick-spread.mjs` (not in this kit).

`review_plan` (MCP/CLI `main.ts review-plan <seat>`, `ops/orchestrator/src/review-plan.ts`) plans accumulated diff depth identically for seat/base/snapshot inputs. Parent-folder `VENDOR.json` excludes files only when reviewed-tree SHA-256 matches; modified/deleted files or unreadable manifests count as own code, without network checks. VENDOR.json/NOTICE are documentation. Documentation (Markdown except CLAUDE.md/AGENTS.md) and tests (`scripts/test-*.mjs`, `*.test.*`, tests directories, Rust test names) alone get zero. Otherwise Jev rates complete own-code diff: risk <0.2 zero, <0.7 one, else two. Security paths have a one-review floor and two only for changed own security lines at risk >=0.7. Missing Jev or cut diff keeps labelled one/two floors. Answers include `vendored`/`jevRisk`; redacted capped text retains paths/stats and per-file hunks. Only complete views can lower the floor; renderer cut detection does not mistake quoted markers for truncation. Focus is concern-split with whole themed diffs; advisory.

Security stems are auth/token/secret/credential/security/permission/install/hook/oauth, plus `ops/orchestrator/src/seat-guard.ts` and access_guards migrations; guard alone is not a stem. Hook alone is excluded under React trees `src/`, `web/`, `server-admin-web/`. Domain knowledge entry/part Markdown is never security; other skill/docs paths retain stem matching (`scripts/test-orch-review-plan.mjs` (not in this kit)).

Multi-domain diffs get `themes` via routing `domainOf`, `unrouted` when unmatched; docs join none. Per-theme Jev/security-floor counts sum; single-theme shape stays. Bad routing maps fail (MCP error, CLI exit 1). Reviewer indexes/snapshots copy the lead index; `seat_land` copies the seat index (`ops/orchestrator/src/land.ts`) with mtime (`ops/orchestrator/src/worktrees.ts`) for git racy-clean detection.
