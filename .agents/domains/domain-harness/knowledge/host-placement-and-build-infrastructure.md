## Host placement and build infrastructure

`HOST_INSTRUMENTS` in `ops/orchestrator/src/placement.ts` probes `ast-grep`, `codegraph`, `memoryctl`, `rg` with load in one SSH call, 1 s per check. `sg` qualifies only if its version identifies ast-grep. `missingHostInstruments` checks enabled seat instruments; `placeSeat` skips missing-tool hosts, naming tools. `ops/orchestrator/src/seats-create.ts` probes forced hosts (including scout parent hosts) once, refusing missing tools/failed probes without relocation. Unknown tools cannot qualify; `orch_status.hostInstruments` shows missing tools.

`mac` means this Mac, `win` requires win32; Claude stays local. AUTO Claude coders with family/host/needs omitted or `any` yield to lighter registered hosts: `lighterHost` reuses probe/ranking/exclusions; `pickFamily` reruns without Claude, retaining loads/reservations/coder cap/paused set. Explicit Claude, `needs: mac`, Mac-only files, no hosts/failed probes keep Claude.

Create `files` are repo-relative, no absolute/UNC/drive/`..`, at most 200 entries of 512 characters. As `taskFiles`, they keep `<project-specific>/` off Windows and `<project-specific>/` on Mac even for an explicit host. Stored as `data.taskFiles` for every role, they supply context when the brief omits files; a reviewer can inherit its author's files/domain. With no files a first coder/bughunter brief is refused; a reviewer queues with `NO_FILES_WARNING` (`ops/orchestrator/src/seats-prompt.ts`, `ops/orchestrator/src/seats.ts`). `author` does not select a tree: review uses `base` resolved in `repo`, or its snapshot. Create refuses a non-snapshot review at its non-snapshot author's starting commit and names the author-worktree snapshot invocation (`ops/orchestrator/src/seats-create.ts`).

`<stateDir>/hosts.json` stores validated `ssh/platform/repo/node`, optional `native`. Only `addHost`/`removeHost` in `ops/orchestrator/src/config.ts` write: `checkHosts`, lock directory, temp, rename; existing names need replace. `ops/orchestrator/src/main.ts` CLI: `hosts list`, `hosts add <name> --ssh --platform --repo --node [--native <JSON object>] [--replace]`, `hosts remove <name>`, `hosts probe <name>`. CLI checks grammar/JSON, writer checks entries. Refusals: exit 1, one stderr line, unchanged bytes; success prints entries.

Add probes node `--version` via `probeHost` in `ops/orchestrator/src/placement.ts` with `sshNodeArgs` from `ops/orchestrator/src/providers/spawn.ts`. Entry/name validation precedes SSH. Results distinguish unreachable (255), node not found (other nonzero), timeout (10 s), node below `engines.node` in `ops/orchestrator/package.json`, or unreadable required range. Failed probes write nothing; `--no-probe` writes explicitly unproved. Node/SSH alias values starting `-` are refused. `probeEnd` kills the SSH group and destroys pipes for host/load/disk deadlines; win32 kills SSH only. Linux prerequisites/proofs live in `docs/agent/linux-host-bringup.md`.

Remote seats use the registered node and checkout's `remote-exec.mjs`; `ssh -R 0:127.0.0.1:<port>` allocates host-loopback ports and rewrites matching Mac-daemon URLs (`ops/orchestrator/src/providers/spawn.ts`). `native` keys `vcvars64`, `pathPrepend`, `cmakePrefixPath` supply MSVC and Qt/CMake/Ninja/ccache. Capture has a 60 s bound below Pi's 75 s get_state bound. The host-state cache key includes vcvars64 path/mtime/size, base PATH and `Microsoft.VCToolsVersion.default.txt`; PATH, INCLUDE, LIB, LIBPATH, VCToolsInstallDir are retained, other unchanged variables omitted. The linker override requires vcvars' `Hostx64\x64\link.exe`, avoiding Git Bash coreutils link.

`syncHostRuntime` in `ops/orchestrator/src/remote-repo.ts` pins host runtime/gate to daemon startup `daemonCheckout`, never lead HEAD. Serve syncs asynchronously; remote create syncs first. Bundle/detached checkout in `withHostClone`: 120 s after turn acquisition, separate ten-minute queue wait. Equal HEAD is untouched; untracked files stay; tracked dirt refuses. `refreshRuntimeHooks` runs `ops/bootstrap/install-git-hooks.mjs` after changed HEAD in-turn, 15 s bound, failure warns only. `orch_status.hostRuntimes` holds last results. `moveCheckout` likewise: 120 s after turn acquisition, separate ten-minute queue wait; `prepareCheckout` holds an unbounded turn.

`ops/orchestrator/build-gate.mjs` queues heavy cargo/rustc, `cmake --build`, ninja except `-t`, and msbuild machine-wide, FIFO by ticket under `<orch state dir>/build-gate`. It resolves tools excluding `ORCH_BUILD_SHIM_DIR`; `ORCH_BUILD_SLOTS` defaults to 2. Dead holder pids are reclaimed; nested `ORCH_BUILD_SLOT` calls pass through. Per-slot floor(cores/K) sets cargo/CMake jobs, ninja `-j`, msbuild `/m` unless caller-set. On win32 killed holders leave reclaimable files; EPERM/EBUSY/EACCES count as busy for 5 s at 50 ms backoff on gate-file operations, while other platforms throw. Busy prune entries stay; busy slot creation counts as occupied; release failure reports without changing build exit. Title `orch-gate <ORCH_SEAT_ID> <tool and args>` excludes `build-gate.mjs`.

`ops/orchestrator/src/build-gate.ts` installs temp/rename shims in `build-gate/bin`; `gateEnv` prepends them and `ORCH_BUILD_SHIM_DIR` locally via `providerEnv` and remotely ahead of native PATH. Win32 uses host-compiled `ops/orchestrator/build-gate-launcher.rs` executables; rustc child PATH excludes Git Bash link. Install serializes on `launcher.lock` with exclusive stale-owner reaping, skips matching launchers, renames running images aside and sweeps them later. `sweepStaleWriterTemps` removes dead-pid temps (above int32 is dead), keeps live writers; failed replace restores and throws, no sh fallback. `gateEnv` retains the last PATH spelling; wiring is dormant without the gate script, and `ORCH_BUILD_GATE` names the host's gate. Win32 remote seats/builds run BelowNormal.

Remote removal preflight in `ops/orchestrator/src/remote-repo.ts` requires a registered, realpath-resolved worktree, not a junction/symlink. Recovery never prunes repo-wide. `ops/orchestrator/src/remote-provision.ts` refuses externally linked `node_modules` before `npm ci`.

`ops/orchestrator/src/target-sweep.ts` runs daily from `serve()` with persisted stamp/exclusive lease; CLI `prune --targets [--dry-run]` also runs it. Candidates are only `target`, `<project-specific>/target`, `<project-specific>/target` in the daemon checkout's `.claude/worktrees/<name>`, plain directories with no symlink path and a Cargo marker at the target root (`CACHEDIR.TAG` or `.rustc_info.json`, a regular non-symlink file: Cargo writes the tag only when it creates the directory itself), no build write within 24 h and no process argv/cwd naming the worktree. Presence/freshness are rechecked before removal; failed process snapshot keeps all targets.
