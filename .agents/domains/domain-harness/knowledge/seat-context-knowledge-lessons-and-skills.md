## Seat context: knowledge, lessons and skills

- `ops/orchestrator/src/context.ts` composes the first message from role duties, the lead's brief, knowledge and lessons for explicit file paths, routed skills, and the closing ban on memory writes and self-commissioned agents.
- Local coder/reviewer/bughunter first messages carry a code map: `codegraph explore` over the brief files in the seat's OWN worktree index, capped at `CODE_MAP_CHARS` (12k), bounded 6 s, process tree killed on timeout (`codeMapSection`); a remote seat's map runs on its host checkout through remote-exec (`remoteCodegraphExplore`). No index, failure or timeout → one labelled line; scouts, researchers and debaters get none. The explore leaves the worktree's codegraph daemon running (5-minute idle exit).
- `ops/bootstrap/knowledge-page-lib.mjs` routes page sections deterministically: `renderKnowledgePage` renders within the page budget; sections that do not fit are indexed by title with the page path, and that index says the sections are NOT shown and to read those covering the question BEFORE more source. Index allowance `KNOWLEDGE_INDEX_ALLOWANCE` (1536 bytes) sits outside the 6 KiB head/section budget and keeps a render under the hook cap `LESSON_CONTEXT_BYTES`. Jev is not asked; `source` is `map` or `none`. Pages split at `## ` headings through one `splitPage`.
- `scripts/memory/eval-knowledge-routing.mjs` measures routing: `freeze` builds a frozen set of 60 first worker turns from orch.sqlite and proxy gold sections overlapping the coder's changed or reviewer's brief-named paths. `score` renders each case through `routeKnowledgeSections`, scores surviving sections within 6 KiB (full/clipped/index-only) into `eval-knowledge-routing.map-score.json`, and reports `goldLineDelivery` (gold anchor lines wholly in the render) and `goldOccurrenceDelivery` (a gold-anchor citation delivered when the ±40 characters around it, cut at line ends, are in the render). `score --routing-commit <sha>` reads that revision's map and refuses a map whose hash is not the frozen one.
- Page layouts: `readKnowledgePage` returns head, TOC, body — one-file page: body from the first `## ` line; split page: each `knowledge/<slug>.md` part in TOC order, `locate` gives file and line. A page splits only when its entry holds `KNOWLEDGE_TOC_MARKER`; the table is not body, so a split changes no body byte nor `body-sha256`. `knowledgeDomainOf`: `knowledge.md` or `knowledge/<slug>.md` under a domain directory names that domain. A split section's part-file line counts against the cap; a named part that cannot be read throws in the seat context. `scripts/split-knowledge-page.mjs` (not in this kit) moves sections to parts, writes the table (title + first 200 characters),, is rerunnable after an interrupt; `--check` proves each part named exactly once.
- Gates read through that reader: `scripts/check-knowledge-anchors.mjs` (not in this kit) selects pages by `knowledgeDomainOf`, judges the assembled page, prints `<part file>:<line>`; `scripts/fix-knowledge-anchors.mjs` (not in this kit) writes into the located part only; `scripts/stamp-knowledge-page.mjs` (not in this kit) takes only the entry page (digest over the assembled body); `ops/harness-kit/build-kit.mjs` (not in this kit) neutralises donor text; `scripts/check-knowledge-history.mjs` (not in this kit) reads no hunk — a line is NEW only when its text (anchors removed) occurs more times in the commit than in EVERY parent, so moves, splits and table reorders send nothing to Jev. Path comparisons compare real paths (`/var`, `/tmp` are macOS symlinks; `isMain`, `scripts/lib/is-main.mjs`).
- Lesson/skill routers cache Jev scores as `{model, ...}` entries, reused only when the model equals pinned `JEV_MODEL` (`ops/bootstrap/lesson-router.mjs`). A routed skill lists checkout-relative when present there, else by absolute path in orch's checkout for a local seat's older branch (`ops/orchestrator/src/context.ts`); remote seats always get checkout-relative paths; nothing is copied into the worktree.
- The session-start skills sensor expects the lead-installed set plus the support-lead set only when the scope's lead directory links one (`supportLeadInstalled`, `ops/bootstrap/session-start.mjs`). That hook also prints the vendored `i-have-adhd` body ahead of diagnostics for every session without `ORCH_SEAT_ID` (leads shape operator replies by it; seats never receive it; a missing file changes nothing).
