# Harness economy audit

Сначала посчитать, что даёт результат, затем убирать то, что его не даёт.
Аудит начинается с измерений; число скилов, выбор модели и отсутствие вызовов
сами по себе не являются вердиктом.

## 1. Зафиксировать окно и результат

- Назвать даты, часовой пояс, машины, провайдеров и проверяемую гипотезу.
- Выбрать единицу полезного результата: завершённая задача с доказательством,
  найденный воспроизводимый дефект, успешная проверка. Отдельно считать повторы,
  пустые ответы и затраты координации; не подменять результат числом вызовов.
- До изменения выбрать метрики: токены по категориям на результат, время до
  результата, число вызовов и объём контекста на вызов. Сравнивать одинаковые
  классы задач и окна; если выборки несопоставимы — указать ограничение.

## 2. Собрать измерения

| Источник | Что извлечь и как считать |
|---|---|
| `~/.claude/projects/**/*.jsonl` | Отобрать записи окна по timestamp; из usage суммировать отдельно `input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`. Удалить дубли синхронизированных сессий и повторных записей одного ответа по session/message ID; описать правило дедупликации. Пропущенные поля учитывать отдельно, не как нули. |
| Те же JSONL по сессиям | Число вызовов, сумма и распределение входного контекста на вызов (input + cache read + cache creation), output, длительность. Разделять короткие и длинные сессии; проверить, где возникает повторное чтение контекста. |
| `~/.claude.json` | Прочитать только `skillUsage` и `pluginUsage`; записать доступное окно счётчиков. Это наблюдение о загрузке, не доказательство пользы или ненужности. Не печатать конфиг целиком. |
| `node ops/orchestrator/src/main.ts pick-stats --since 30d --json`; orch store (`turns.usage`) | Зафиксировать окно; взять сводку по family/role/model/effort, длительности и токенам. Для разбивки категорий читать JSON `turns.usage`: `inputTokens`, `outputTokens`, `cacheReadTokens`, `cacheWriteTokens`, по уникальному turn ID. Отсутствующий/невалидный usage учитывать отдельно, не как ноль; медианы сводки не суммировать как общий расход. |
| Канон скилов | `find .agents/skills -name SKILL.md -exec wc -lc {} +` — строки и байты. Каталог доступных скилов и реально загруженные тела считать раздельно; байты не выдавать за токены. |
| Ссылки в дереве | Начать с `rg -l "<имя>" -g '!*.jsonl'`; для полного охвата повторить с `--hidden --no-ignore`, исключив `.git`. Проверить ссылки из других скилов, сенсоров и конфигурации, включая ссылки по пути. |
| Стартовый контекст | Измерить байты `CLAUDE.md`, вывод SessionStart и его бюджет в `ops/bootstrap/session-start.mjs`; handoff и поиск памяти — по запросу оператора и по мере необходимости (не часть SessionStart). Посчитать фактически доставленные MCP-схемы и контекст мест orch (`ops/orchestrator/src/context.ts`), отдельно по runtime и месту. Число инструментов не заменяет размер схем. |

Хранить воспроизводимую команду/скрипт агрегации и путь к результату. Для каждого
числа указывать окно, единицу, источник и пропуски. Токены разных категорий
не равны денежной стоимости или списанию лимита подписки: для этого нужна
отдельная проверенная модель тарификации.

## 3. Принять решение по порогам доказательства

1. Разложить расход на стартовый контекст, повторное чтение истории, вывод и
   координацию. Ранжировать кандидатов по измеренному расходу на полезный результат.
2. Для гипотезы экономии нужны сопоставимые **до/после**, положительная разница,
   превышающая наблюдаемый разброс, и сохранённый результат. Иначе вердикт:
   «экономия не доказана». Универсальный процент не придумывать.
3. Ноль загрузок — повод проверить триггер и наличие подходящих задач в окне.
   Непопадание в триггер не означает, что скил не нужен.
4. Порог удаления скила: подтверждённое отсутствие нужной функции/уникального
   сценария **и ноль входящих ссылок из других скилов и сенсоров**. При ссылках
   удаление запрещено; перенос контракта — отдельное согласованное изменение.
5. Сначала предложить минимальное изменение с измеримой пользой. Источник
   конфигурации — дерево репозитория и его установщики; не править установленную
   копию. Защитные гейты не снимать ради экономии. Делегация следует действующему
   [orch-team](../orch-team/SKILL.md); не выбирать исполнителя по догадке о цене.

## 4. Проверить изменение

- Для скилов: `npm run check:skill-contract`, `node scripts/check-skills-drift.mjs`,
  `node scripts/check-skill-map.mjs`. Проверки `check:doc-graph` и `check:harness-audit` не запускают тесты;
  курируемый набор тестов запускает CI или прогон перед деплоем, не агент (#12881).
- Для изменённого хука/доставки: `bash -n` хука и поведенческая проверка в новой
  сессии после применения конфигурации. Текущая сессия не доказывает новый старт.
- Повторить исходный замер. Отчёт: `claim · evidence(file:line|command|URL) ·
  confidence · checked · not-checked`; не измеренные расходы и провайдеры — явно
  в `not-checked`. Без повторного замера не заявлять достигнутую экономию.

сессии и не норматив для других машин, моделей или периодов.

- Окно 14 дней, 2026-09-02…16: 57 168 вызовов; input 14,26 млн, output 67,84 млн,

  следующего замера; агрегаты не изолируют причинный эффект модели/скила и не
