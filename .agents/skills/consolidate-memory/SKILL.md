Ты консолидатор памяти. Магазин — memoryd на NAS через `memoryctl`; локальный `memory.db` устарел. Правила суждения те же, что
у `admit` (merge / supersede / contradict / reject) и у `curate` (append-only, supersede,
никогда не удалять). Этот скил добавляет одно: что можно делать **без спроса каждый день**,
а что нельзя никогда.

## Железный инвариант: активное не трогается

Прежде чем что-то менять, проверь по этому списку. Скан печатает пометку `ЗАЩИЩЕНО` сам,
но ответственность на тебе.

- **Задача активна**, если: `status != open` · `claimed_by` не пуст · `P0` · на неё
  ссылается `depends_on` другой открытой · обновлена меньше 24 ч назад.
- **Урок активен**, если `links.status=active` И якорь `keep` по `sweep-anchors`.
- **Handoff активен**, если он самый свежий на своём треке, или его трек `status: blocked`,
  или среди объявленных им задач есть незакрытая.
- **Никогда** не трогай `pinned=1` и записи, изменённые за последние 24 ч.

Активное не сливается, не архивируется, не закрывается — даже если выглядит дублем.
Такой случай уходит в предложения, а не в действие.

## 1. Скан

```bash
node .agents/skills/consolidate-memory/scan.mjs
node scripts/memory/sweep-anchors.mjs --json
```

`scan.mjs` только читает сервис; `sweep-anchors.mjs` публикует CAS-отчёт `anchor-sweep-latest` (для пробы без записи — `--no-report`). Недоступный сервис — ошибка, локального резервного источника нет. Пороги правятся флагами: `--stale-days 30
--orphan-days 30 --task-jaccard 0.6 --lesson-jaccard 0.7 --anchor-budget 24576`. Возраст B1 — `B1_ARCHIVE_DAYS` (14), тот же что у `archive-handoff.mjs`; флага у скана для него нет.

C3 считает бюджет **на якорь**, а не на домен: домен целиком не приезжает ни в
один контекст, и счётчик домена больше не гейтит нигде.

## 2. Что применяешь сам (авто-классы)

Только эти три. Каждое — доказуемо без суждения, каждое обратимо (цепочка supersede цела,
ничего не удаляется).

**A1 — точный дубль задачи.** Скан пометил `свободно` (иначе пропусти).
```bash
memoryctl task update --id <дубль> --status cancelled --evidence "дубль #<оригинал>" --title "MERGED-INTO: #<оригинал> — <исходный заголовок>"
```
Заголовок ≤200 символов. Если у оригинала пустой `next_action`, а у дубля есть — перенеси:
`memoryctl task update --id <оригинал> --next "<шаг>"`. Больше в оригинале не меняй ничего.

**B1 — handoff, чей трек продолжен свежим.** Условия: трек объявлен, есть более новый handoff
того же трека, все объявленные задачи закрыты, возраст ≥14 д, не pinned, текущий статус трека
не `blocked`. Скан печатает статус трека в строке кандидата: `[track · status]`.
```bash
node scripts/memory/archive-handoff.mjs --id <n> [--id <n> ...] [--dry-run]
```
Скрипт сам проверяет все условия (включая живость записи и заголовок-историю) и отказывает по
каждому, печатая причину и ничего не записывая; `--dry-run` показывает, что применилось бы.
Тело переносится байт-в-байт и сверяется SHA-256 перечитанной новой версии: архив — это статус,
а не пересказ. `--no-open-work` здесь честен ровно потому, что все хвосты закрыты — это и есть
условие класса.

**C1 — урок с мёртвым якорем.** `sweep` дал `gone`, якорь конкретный (не glob, не `?`), и файла
нет **ни в дереве, ни в `git HEAD`** (`git cat-file -e HEAD:<файл>` падает). Отсутствие только в
дереве — это переключённая ветка, а не удаление: тогда не трогай.
```bash
node scripts/memory/retire-lesson.mjs --id <n> --reason "якорный файл <path> удалён из HEAD"
```
Дубль урока ретайрится с `--merged-into <id>`, а не с общей причиной.

## 3. Что только предлагаешь (никогда не применяешь молча)

- **A2 смежные задачи** — похожие формулировки. Слияние смежного меняет смысл хвоста; это решение
  оператора или отдельная сессия.
- **A3 «похоже закрыто»** — совпадение с закрытой задачей или трек, объявленный `done`. Закрытие
  требует доказательства (коммит, замер, сенсор), а не совпадения слов. Если доказательство
  нашлось в этом же прогоне — закрой `memoryctl task done --id <n> --evidence "<sha | memory#id>"`
  (без `--evidence` сервис откажет) и повтори доказательство в отчёте.
- **B2 handoff без трека** старше 30 д.
- **C2 пересекающиеся уроки** на одном якоре, **C3 домен сверх бюджета**, домен вне карты
  маршрутизации (уроки в нём недоставляемы — это дефект, а не стиль).
- **D противоречия** (`CONTRADICTS id N`) — только оператору, молча не решаются никогда.

## 4. Отчёт (и почему рутина не плодит мусор)

Отчёт — одна CAS-запись, версия за версией, а не новая запись в день.
```bash
memoryctl registry-read --key consolidate-latest      # взять version (нет ключа -> 0)
memoryctl registry-update --key consolidate-latest --expected-version <v> --body-file <отчёт>
```
Exit 9 = гонка: перечитай версию и повтори один раз.

Тело отчёта: дата · счётчики просканированного · что применено (по классам, с id) ·
что предложено · что защищено и почему · что не удалось.

Дальше:
- **Есть предложения** → одна задача с треком `memory-consolidation`. Если такая уже открыта —
  не создавай вторую, обнови: `memoryctl task update --id <n> --next "<дата>: N предложений"`.
  Иначе `memoryctl task create --title "Разбор консолидации памяти <дата>" --priority P1
  --track memory-consolidation --next "<сводка>"`.
- **Что-то применено** → `memoryctl append --kind decision --title "consolidate <дата>"
  --body "<счётчики>" --agent consolidator`. Ничего не применено — не пиши ничего.
- **Handoff рутина не пишет.** Ежедневный handoff — это 365 записей в год в хранилище, которое
  она же чистит.

## Границы

- Мутации только через `memoryctl` / `scripts/memory/*`. Прямой SQL на запись — никогда:
  гейты магазина живут в сервисе.
- `CLAUDE.md`, `AGENTS.md`, скилы, хуки рутина не правит. Нужна правка контракта — предложение
  оператору, дальше `edit-contract-mirror`.
- Промоушен уроков из inbox в active — не здесь, это решение `/curate`.
- Сервис лежит → скажи это и выйди. Память никогда не блокирует работу.
